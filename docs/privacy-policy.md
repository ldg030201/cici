# cici 개인정보 처리방침

**적용 대상:** 크롬 확장 프로그램 "cici — Claude in Chrome 기기 ID" 및 `cici` 명령줄 도구
**시행일:** 2026-09-04
**소스 코드:** <https://github.com/ldg030201/cici> (MIT)

## 한 줄 요약

**cici 는 개인정보를 수집하지 않습니다. 저장하지 않습니다. 전송하지 않습니다. 판매하지 않습니다.**
네트워크 요청을 한 건도 하지 않습니다.

---

## 1. 수집하는 정보

없습니다.

cici 는 사용자 정보를 수집하지 않습니다. 서버가 없고, 계정이 없고, 로그인이 없고,
애널리틱스가 없고, 광고가 없고, 오류 보고 전송이 없고, 원격 코드가 없습니다.

## 2. 전송하는 정보

없습니다.

cici 는 어떤 서버에도 접속하지 않습니다. 확장의 콘텐츠 보안 정책(CSP)은
`default-src 'self'; connect-src 'self' file:; object-src 'none'` 으로 설정되어 있어,
원격 주소로의 연결이 코드 수준이 아니라 **브라우저 수준에서 차단**됩니다.
확장에 담긴 코드는 전부 설치 패키지 안에 있으며 외부에서 내려받는 코드가 없습니다.

## 3. 저장하는 정보

확장은 자기 자신의 `chrome.storage.local` 에 **난수 하나**를 저장합니다.

| 키 | 값 | 목적 |
| --- | --- | --- |
| `__cici_nonce` | 임의로 생성한 UUID (예: `3f2a…`) | 확장이 **어느 크롬 프로필에서 실행 중인지** 판별 |

확장에는 자신이 어느 프로필에 있는지 알아낼 수 있는 API 가 없습니다. 그래서 팝업을 열 때마다
새 난수를 만들어 자기 저장소에 쓰고, 프로필들을 훑어 그 난수가 기록된 프로필을 찾습니다.
그곳이 현재 프로필입니다.

이 값은 사용자 정보가 아니며, 매 실행마다 새로 만들어져 이전 값을 덮어씁니다.
어디로도 전송되지 않고, 사용자의 브라우저 밖으로 나가지 않습니다.

그 밖에 cici 가 디스크에 쓰는 것은 없습니다. 명령줄 도구는 아무것도 저장하지 않습니다.

## 4. 읽는 정보

cici 는 다음 로컬 파일을 **읽기 전용**으로 읽습니다.

| 대상 | 무엇을 위해 |
| --- | --- |
| `<user-data-dir>/` 및 그 하위의 디렉터리 목록 | 이 컴퓨터의 브라우저 프로필을 찾기 위해 |
| `<user-data-dir>/Local State` | 화면에 표시할 프로필 이름과 계정 이메일을 읽기 위해 |
| `<프로필>/Local Extension Settings/fcoeoabgfenejglbffodgkkbkcdhcgfn/` | Claude in Chrome 확장이 저장해 둔 `bridgeDeviceId` 와 `bridgeDisplayName` 을 읽기 위해 |
| `<프로필>/Local Extension Settings/<cici 자신의 id>/` | 위 §3 의 난수를 찾아 현재 프로필을 판별하기 위해 |
| `<프로필>/Extensions/<확장 id>/` | 설치된 Claude 확장의 버전을 읽기 위해 (명령줄 도구) |

읽은 값은 화면에 표시하기 위해서만 사용되며, 화면을 닫으면 사라집니다.
어디에도 축적하거나 기록하지 않습니다.

### 읽지 않는 것

cici 는 다음을 **읽지 않으며, 읽을 수도 없습니다**(해당 권한을 요구하지 않기 때문입니다).

* 방문 기록, 북마크, 다운로드 기록
* 쿠키, 세션, 로그인 정보, 저장된 비밀번호
* 열려 있는 탭의 주소나 페이지 내용
* 입력 내용, 클릭, 마우스 움직임
* 다른 확장 프로그램의 저장소 — Claude in Chrome 의 저장소를 파일로 읽는 것 외에는 접근하지 않습니다

확장이 요구하는 권한은 `storage` 와 `host_permissions: ["file:///*"]` 둘뿐입니다.
`tabs`, `scripting`, `webRequest`, `cookies`, `history`, `nativeMessaging`, `<all_urls>` 는
요구하지 않으며, 콘텐트 스크립트와 백그라운드 서비스 워커도 없습니다.

## 5. 쓰기 · 변경

cici 는 크롬의 프로필 디렉터리에 아무것도 쓰지 않습니다.
파일을 만들거나 고치거나 지우지 않으며, LevelDB 의 `LOCK` 파일도 잡지 않습니다.
그래서 브라우저가 실행 중인 상태에서 사용해도 안전합니다.

Claude in Chrome 확장의 저장소를 포함해, 다른 확장 프로그램의 데이터를 변경하지 않습니다.

## 6. 파일 접근 권한에 대하여

확장이 위 §4 의 파일을 읽으려면 사용자가 `chrome://extensions` 의 확장 세부정보에서
**"파일 URL에 대한 액세스 허용"** 을 직접 켜야 합니다.

* 이 설정은 크롬 웹스토어에서 설치했을 때 **기본적으로 꺼져 있습니다.**
* 확장이 스스로 켤 수 없습니다. 요청하는 API 자체가 없습니다.
* 사용자가 언제든지 같은 자리에서 다시 끌 수 있습니다. 끄면 확장은 아무 파일도 읽지 못합니다.
* 이 설정은 크롬 프로필마다 따로 적용됩니다.

## 11. 검증 방법

이 방침의 모든 주장은 소스 코드로 확인할 수 있습니다. 전체 소스가 공개되어 있고,
확장은 번들러나 압축 과정 없이 **사람이 읽을 수 있는 그대로** 배포됩니다.

| 확인할 것 | 방법 |
| --- | --- |
| 네트워크 요청이 없다 | `extension/` 에서 `fetch(` 를 검색하면 `file:` URL 만 나온다. `XMLHttpRequest`, `WebSocket`, `sendBeacon` 은 없다 |
| 원격 코드가 없다 | `manifest.json` 의 `content_security_policy` 확인. 외부 `<script src>` 가 없다 |
| 쓰기가 없다 | 확장이 쓰는 API 는 `chrome.storage.local.set` 하나뿐이며 `__cici_nonce` 에만 쓴다. CLI 는 `readFile`/`readdir`/`stat` 만 쓴다 |
| 권한이 둘뿐이다 | `extension/manifest.json` 의 `permissions` 와 `host_permissions` |

브라우저 개발자 도구의 네트워크 탭을 열어 둔 채 팝업을 열어 보아도 됩니다. 요청이 잡히지 않습니다.
